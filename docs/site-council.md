# Site Council — 紹介サイト改訂のための専門家評議会

2026-08-06 設置。目的: 紹介サイトを「何ができるか不明確」な状態から、
対象読者が**自分ごととして価値を理解し、試したくなる**状態へ引き上げる。

この評議会は実在の人物の発言を再現するものではない。各部門で確立された
方法論を参照し、このサイトの設計判断に適用する記録である。

## 招集メンバー（役割と参照基準）

| 部門                   | 参照する世界水準                           | 担当領域                               |
| ---------------------- | ------------------------------------------ | -------------------------------------- |
| ポジショニング         | April Dunford『Obviously Awesome』の方法論 | 誰に・何を・なぜ代替より優れるか       |

## 現状サイトの監査所見

1. **ヒーローが「何か」しか言っていない** — 「バイリンガル Claude Skill で
   16:9 デッキを作る」は仕様説明であり、医師のペイン（学会前夜のスライド
   地獄、英語発表の負担）に接続していない。
2. **生成物が見えない** — デモはリンク先に行かないと見えない。
   「依頼文 → 完成スライド」の対比がファーストビューにない。
3. **誰のためかが曖昧** — 抄読会をする研修医、学会発表する指導医、
   英語デッキに苦戦する研究者、それぞれの具体的シーンがない。
4. **信頼の根拠が埋もれている** — 安全ゲート・テスト数・オフライン検証は
   差別化の核心なのに、特徴リストの中で埋もれている。
5. **CTA が弱い** — 「Open the live catalog」は行動の理由にならない。
   導入手順は「3分で試せる」ことが伝わっていない。

## 導出された改訂方針（v2）

1. **ヒーローで「言うだけで、学会スライド」を実演する**
   左に実際の依頼文（日英）、右に生成されたスライド画像。仕様ではなく
   体験を見せる。
2. **ユースケースを職務シーンで書く**
   抄読会 / 学会発表 / 症例カンファレンス / 教育講演の4シーンに、
   それぞれ実際の依頼文例を添える。
3. **信頼性を数値で示す** — 66 コンポーネント、55+ 自動テスト、
   外部リクエスト 0、18px 投影フロア、axe 違反 0。
4. **安全ゲートを「誠実さ」として前面に** — 捏造しない・停止する設計は
   制約ではなく、医療プロダクトとしての差別化。
5. **CTA は「3分で試す」** — clone → install → 依頼の3ステップであることを
   明示し、デモへの導線は副次的に。
6. **作者の明示** — 現役小児科医が自分のペインから作った、という
   ドメイン真正性。

## トーンの制約

- 誇大広告にしない（「AI が全部やる」ではなく「医師の確認を前提とする」）
- 医療の安全性に関わる記述は safety gate の実装と1対1で対応させる
- 合成例であることの明示は全デモリンク近辺に維持する
